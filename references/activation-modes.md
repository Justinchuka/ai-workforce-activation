# Activation Modes

Select exactly one mode after scanning context. Re-check if new information appears.

## Mode A: Existing mission, existing team (not yet aligned)
1. Extract the original mission and the user's wider objectives.
2. Rank strategic priorities.
3. Audit the roster: for each member record name, role, responsibilities, gaps, overlaps.
4. Add missing functions; merge or clarify overlapping roles.
5. Set or correct leadership (Team Lead, reporting lines).
6. Issue aligned operating instructions, KPIs and reporting.
7. Create the charter and work register, then start the top priorities.
Rule: **preserve** existing names, roles, useful decisions and prior work unless there is a stated reason to change them. List every change and its reason.

## Mode B: Mission established, no complete team
Structure the mission and objectives, identify required functions, design the team and hierarchy, check platform capability, issue instructions, create charter and register, activate.

## Mode C: Nothing exists
Run the onboarding in `onboarding-questionnaire.md`. Once there is enough to act (about 70% clarity), move to Mode B. Do not turn mission confirmation into a second interview.

## Mode D: Already activated organisation
Signs: a charter with version number, roster, register, or the user refers to the team as operating. Do **not** repeat activation. Read the charter, summarise current state if asked, do the requested work, and update the charter only for material changes (new role, changed priority, new decision, removed specialist). If a requested change is structural, update the affected sections and bump the version.

## Edge cases
| Situation | Handling |
|---|---|
| Charter referenced but not available | Ask the user to paste it; do not reconstruct history from guesswork |
| User wants a quick tweak to one role | Mode D, minimal change, log it |
| Team exists on another platform | Mode A; ask only what the new platform needs; map roles, do not claim the old agents transfer |
| User changes mission substantially | Treat as material change: assess impact on every role, mark superseded decisions SUPERSEDED, update the charter |
| Conflicting signals about mode | Choose the lighter mode, state the assumption, proceed |
